## 1. 常见问题 × 设计防线对照

### 1.1 稳定类

| 常见问题 | 设计防线 | 状态 |
|---|---|---|
| 重复执行（调度重跑/用户重试） | 三层幂等：检测幂等、`idempotency_key` 任务幂等、诊断懒加载 | ✅ 已解决 |
| 任务失败（LLM 超时/网络抖动） | 指数退避重试（5s→10s→20s）+ `failed` 状态可查 | ✅ 已解决 |
| 多 Worker 抢同一任务 | `SELECT ... FOR UPDATE SKIP LOCKED` 抢占，任务只消费一次 | ✅ 已解决 |
| 服务重启丢数据 | 任务存 DB（持久化队列），非内存队列 | ✅ 已解决 |
| Worker 崩溃后任务卡死 | `recover_stale_tasks()` 超时回收：调度器每 5 分钟执行 + Worker 启动自愈 | ✅ 已解决 |
| Worker 取任务时数据库断连 | 主循环 try/except + 退避重试，Worker 不退出 | ✅ 已解决 |
| 单机 MySQL 故障 | 有备份脚本，无自动化恢复演练 | ⚠️ 未完全解决 |

## 2. 未解决缺口（按优先级）

| # | 缺口 | 影响 | 建议补法 | 工作量 |
|---|---|---|---|---|
| 1 | Worker 进程被外力终止后自动拉起（断电/系统重启） | 需人工重新启动 | 任务计划程序"失败重启"或 NSSM 服务 | 中 |
| 2 | 报告质量自动质检 | 仅有用户反馈，无自动检查；证据与结论矛盾的报告可能漏出 | 规则检查：结论引用的证据是否被工具实际返回 | 中 |
| 3 | 备份恢复演练 | 备份可能不可用，未验证过从备份恢复 | 在空库上执行一次 restore 演练 | 小 |
| 4 | MySQL 高可用 | 单机故障即服务中断 | 主从复制或云 RDS | 中 |

## 3. 设计总结

**核心设计：**

1. **安全纵深**——以"LLM 不可信"为前提：工具白名单 → 参数强校验 → 只读 DB 账号兜底。LLM 被诱导时，破坏上限为一次合法参数的只读查询。
2. **幂等体系**——检测幂等、任务 `idempotency_key`、诊断懒加载三层幂等，重复执行不产生重复数据。
3. **可追溯**——run_id 贯穿 agent_runs / tool_calls / sql_logs 三件套，配合"数据错/工具没调/分析错"三对一归因，可完整重放一次诊断。

**工程取舍：**

- 规则引擎不依赖 LLM（可复现、可解释、零成本），Agent 仅负责调查取证
- 指标注册表作为口径唯一来源，更换数据源只需修改口径配置
- 宽表预聚合 + 只读账号，兼顾查询性能与安全边界
- 测试全离线（SQLite + MockLLM），不依赖外部服务
- 任务队列用 DB 而非 Kafka/Redis（数据量级别不需要；DB 队列自带持久化、可审计、事务一致）

## 4. 上线建议

| 阶段 | 建议动作 |
|---|---|
| 立即 | 无（当前缺口均可延后） |
| 上线前 | 备份恢复演练一次，确认备份可用 |
| 正式运行 | Worker 自愈（缺口 1）+ 报告质检（缺口 2）+ 多进程 Web/HTTPS/云数据库 |
| 规模化 | Redis 队列 + 多 Worker、ClickHouse、Prometheus 监控 |
