# 数据与使用说明

本文是操作入口；架构理由见[设计说明](设计说明.md)，恢复与迁移见[Worker 文档](Worker运行与恢复说明.md)。

## 1. 配置与使用前提

建议使用项目虚拟环境。以下命令以 Windows 的 `.\.venv\Scripts\python.exe` 为例；Linux/macOS 可替换为 `.venv/bin/python`。已有环境应复用，不要为了测试重新导入数据或混装依赖。新机器先安装 Python 3.14 和 Node.js，再按项目依赖文件配置环境；Node.js 用于前端脚本回归。

配置定义见 [app/config.py](../app/config.py)，模板见 [.env.example](../.env.example)。应用读取项目根目录 `.env`，同名环境变量优先；模板里的 Key/密码是占位符，不能直接用于真实服务。

| 配置 | 当前语义 |
|---|---|
| APP_ENV | development/test/production；开发配置不要暴露公网 |
| DB_* | 数据库主机、端口、库名及读写账号；模板端口 3306，操作前核对部署环境 |
| LLM_API_KEY | 开发/测试空值走 Mock；填写有效 Key 才调用模型；production 禁止空值/模板 Key 自动降级 |
| API_KEY_SCOPES | 按 Key 显式分配操作权限；显式权限优先于旧 API_KEYS |
| ALERT_WEBHOOK_URL / SECRET | URL 空则不外发；SECRET 非空才附加 HMAC 签名，不能假设配置 URL 就自动有签名 |
| MCP_* | 默认关闭的可选 stdio 适配实验，日常 Agent 无需启用；tools:read 显式授权，见 MCP 学习说明 |
| Agent/Worker 预算 | 字段、默认值与次数区别见 Worker 文档 |

production 还要求清空旧式 API_KEYS，使用至少 32 字符且有 scope 的 Key、MySQL、不同读写账号以及非默认数据库密码。这些启动检查不代替真实账号授权、HTTPS 和部署验收。

新机器安装依赖、建库、配置账号都属于环境变更，需先确认范围。[create_users.sql](../scripts/create_users.sql)目前包含 DROP 授权与 '%' 来源账号，且密码为占位符；不可按注释当作生产最小权限脚本直接执行。已有数据库不要重跑初始化/全量导入。

## 2. 数据口径：能看什么，不能推断什么

原始数据为 Retailrocket 的 events、item_properties 和 category_tree CSV。导入后主要结构：

| 表 | 内容 |
|---|---|
| raw_events / category_tree / visitor_first_seen | 行为、类目关系及访客首次出现时间 |
| daily_item_stat | 按天、商品及 all/day_type/new_user/category 维度聚合 |
| item_price / item_category / item_availability | 最新价格映射、类目映射、可用性观察记录 |
| anomaly_event / task | 规则异常与诊断队列 |
| agent_checkpoint / agent_run / diagnostic_report / tool_call_log | 恢复状态、运行汇总、报告及审计 |
| report_review | 报告版本审查、异常快照、经验授权及停用 |
| review_draft | 单条反馈的模型提炼草稿、幂等占位、来源摘要与模型用量；草稿不直接进入经验库 |

关键限制：

- 漏斗是 view → addtocart → transaction；不是完整的曝光、点击、支付事件链。
- click_rate 为 UV / view_count × 100%，cvr 为 transaction_count / UV × 100%；按日 UV 累加不等于窗口内去重访客数。分母为零时公式返回 0，不代表观测充分。
- 导入器将属性 790 的数值映射为最新价，GMV 用成交笔数乘最新价估算；历史生效价、字段语义及货币单位仍需核实，不能据此计算“实际损失”。指标配置现仍含“元”等标签，不应把标签当成已核实事实。
- 不可用日期是观察点，未重建完整状态区间；其他哈希属性不能随意赋予业务含义。
- metric 的 `summary.coverage.current/previous` 分别描述两期日记录，`summary.windows` 给出准确边界；旧 `data.coverage` 保留为当前窗口别名。任一期缺行就不解释环比，缺行可能是无事件或漏数据，不自动补零。
- `summary.changes` 含差值、单位、相对变化和状态：insufficient_coverage/undefined_denominator 的变化为 null；zero_baseline 不计算相对百分比。CVR 等比例的差值是百分点，记录齐全也不代表数据已审计。
- `summary.sample_counts` 给出两期访客与成交数量；MySQL Decimal 计数统一为 JSON 数字。任一期成交不足 20 笔时增加谨慎提示；20 是提醒阈值，不是统计显著性检验。
- peer 只有当前窗口横向比较，不能据此判断大盘历史趋势。类目级异常使用代表商品辅助调查，不等于完整类目归因。

接入新业务数据需同时核对导入映射、计算公式、工具输出和标签，不是只改配置即可迁移。

## 3. 启动与查看

以下启动操作会改变服务状态，需确认目标与权限；不要一次运行所有命令。

```powershell
# 先单独启动 API；启动会检查结构，必要时创建缺失表
.\.venv\Scripts\python.exe scripts/manage_services.py start api

# 已启动 API 的健康检查
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/healthz'

# 启动 Worker 前只读盘点；不领取任务或调用模型
.\.venv\Scripts\python.exe scripts/worker_preflight.py

# 确认没有重复 Worker、旧版本和未授权积压后，另开终端前台运行
.\.venv\Scripts\python.exe scripts/run_worker.py
```

Worker 启动会回收失效任务、消费符合条件的待办，可能触发模型调用。前台 Ctrl+C 停止领取并等待在途任务结束；`manage_services.py stop` 与 `stop_all.bat` 使用强杀，不是优雅排空。服务状态命令不能追踪所有手工前台进程，PID 文件也不等于进程健康。

Scheduler 默认按当前日期每天检测，历史固定数据通常应手动选择历史窗口。不要默认启动 scheduler / start_all；调度器不仅检测，还会入队和回收任务。

面板：[http://127.0.0.1:8000/api/v1/monitoring/dashboard](http://127.0.0.1:8000/api/v1/monitoring/dashboard)。页面本身无 Key，数据请求需 Key；前端不持久保存 Key，刷新需重输。不要将密钥粘入文档、日志或 Git。

页面右上角 `X-API-Key` 填的是本项目后端访问密钥，**不是 `LLM_API_KEY`**。优先使用 `API_KEY_SCOPES` 中拥有 `report:read` 的密钥；开发模式也可使用 `API_KEYS` 中未被显式限制的密钥。只复制值，不带变量名、逗号或外层引号；输入后按 Tab 触发加载，不需要在聊天中提供密钥。未输入时页面的“加载失败/Key 缺失”不代表 API 没有启动。

Key 改变后会同时刷新统计和异常列表，并重置分页；迟到的旧请求不能覆盖新结果。401 提示输入 Key，403 提示缺少权限，429 提示限流，5xx 提示后端错误；只有接口成功返回空列表才显示“没有符合条件的异常”。30 秒自动刷新仍只更新监控，不打断异常列表分页；新诊断后可切换“仅已诊断”重新加载列表。

“诊断次数”统计选定时间窗口内的运行记录，并不是全部商品或异常数量；异常列表展示未关闭事件，时间口径不同。API 负责提供页面和接口，不会自动为全部历史异常创建任务；默认检测流程只为新发现的异常入队，已有异常的补诊断需要单独确定范围。批量启动 Worker 会消耗待执行任务，可能产生模型费用，不能把“打开页面”等同于“全部诊断”。

报告弹窗按四个问题阅读：整体变化、集中位置、尚未确认、下一步核查。服务端新报告带版本和规则检查状态；旧报告仍可阅读，但会提示未按当前规则复核，没有定位证据会明确说明。建议同时显示依据、责任、P0/P1/P2 和验收条件；这些建议不会自动执行。

人工审查需要 `report_review`、`review_draft` 两表，不重写已有报告。部署前确认建表和 API 重启范围；启动的 create_all 会创建缺失表，因此不能把重启误当成纯读取操作。只查看页面和历史报告仍仅需 API，不必启动 Worker/Scheduler。已有报告使用新展示，但不会自动得到新诊断结论；重新诊断和模型复测需另行确认，重复提交同一异步幂等键可能仍返回旧报告。实际部署/验收情况见进度文档。

真实 LLM 调用需要执行诊断的 API 或 Worker 进程可访问配置的模型站点；数据库连通不代表模型网络连通。联网诊断和隔离测试应分别配置运行条件，不应为测试取消沙箱或扩大权限。同步调试诊断发生可重试错误时可能留下 waiting_retry，但没有对应排队任务，不表示后台正在恢复；不要不停点击来重试。

### 审查一份报告

1. 打开报告，点击“已审查”，先出现反馈表单，此时尚未写入。
2. 选择正确/部分正确/不正确/暂不能判断，填写一段反馈。点击“自动提炼经验并预览（调用模型）”会发送本条反馈、异常信息和报告短结论，产生模型费用；同反馈重复点击读取原草稿，不自动追加调用。
3. 核对或修订回填的可参考经验、应避免误判、适用条件与核查依据，并勾选草稿确认。如希望未来同类诊断参考，再独立勾选经验授权并至少保留一项经验。不要填写个人信息、密码、密钥或无关敏感数据；更改原反馈后旧草稿失效，不能直接套用。
4. 点击“确认审查并保存反馈”。报告显示“已审查”，异常仍保持原处理状态；新版本报告需重新审查。写入需要 `feedback:create` 权限，仅能读取的 Key 不足以提交。
5. 如经验不再适用，点击“停止用于后续诊断”并确认；不删除原反馈，也不重新启用之前已停用的记录。

未配置模型、预算不足或提炼失败时，可跳过提炼，只保存原文或手工填写；不会自动使用 Mock 伪造真实草稿。每报告每 Key 默认最多 3 份不同反馈草稿；相同失败输入不重跑。进程中断可能留下 generating，应核查记录或手工处理，不把刷新页面当成重新付费的授权。配置项 `FEEDBACK_LLM_TOKEN_BUDGET=6000`、`FEEDBACK_LLM_MAX_OUTPUT_TOKENS=1200`、`FEEDBACK_LLM_TIMEOUT_SECONDS=30`、`FEEDBACK_MAX_DRAFTS_PER_REPORT=3`；这些限制不保证供应商账单硬封顶。

经验副本在 `LOG_DIR` 的父目录下 `knowledge/reviews/`，默认是项目内该目录；停用另存 `review-<id>-disabled.md`。这些运行产物不入 Git。Markdown 导出失败时审查仍已提交；相同反馈再次提交可补写尚不存在的文件，已存在但不一致的文件不自动覆盖，须核查后处理。数据库是读取经验的来源，手改 MD 不会自动改变模型参考内容。反馈看板分别统计旧星级评分和人工审查，审查数量包含历史报告版本，不当作诊断准确率。

## 4. API 路径与权限

| 接口 | 权限/用途 |
|---|---|
| GET /healthz | 无 Key；数据库基本连通性，不是 Worker 健康验收 |
| GET /openapi.json；GET /docs | 无 Key；均无 /api/v1 前缀。/docs 的交互资源可能受当前 CSP 限制 |
| POST /api/v1/diagnostics | diagnosis:create；默认异步，production 禁止 sync=true |
| GET /api/v1/tasks/{task_id} | report:read；状态、结果、尝试数、心跳、租约与截止时间 |
| GET /api/v1/monitoring 及 history、slow-queries、cost、feedback、alerts | report:read；全局监控，成本为配置单价估算 |
| GET /api/v1/monitoring/anomalies | report:read；异常列表 |
| GET /api/v1/monitoring/reports/{anomaly_id} | report:read；按异常查询报告 |
| POST /api/v1/import/daily-stat | data:import；CSV 追加导入 |
| POST /api/v1/feedback | feedback:create；对已有报告反馈 |
| POST /api/v1/monitoring/reports/{run_id}/review | feedback:create；提交一次版本审查，verdict/comment 必填，经验与授权可选 |
| POST /api/v1/monitoring/reports/{run_id}/review-draft | feedback:create；verdict/comment 必填，自动提炼或返回已有草稿，会调用模型及写草稿记录 |
| POST /api/v1/monitoring/reports/{run_id}/memory/disable | feedback:create；停用后续经验参考，保留原反馈 |

MCP 不属于上述 HTTP 路由：独立 `tools:read` 只用于本机工具服务，不授予报告读取或诊断权限；接入和演示见[MCP 学习说明](MCP接入与学习说明.md)。

业务请求使用 `X-API-Key`。当前 scope 不提供用户/店铺数据隔离，report:read 可访问全局报告和监控。

异步诊断请求字段：正整数 item_id、start_date、end_date，可选 anomaly_id，以及 `sync:false`。日期必须正序、差值不超过 90 天；异常必须属于对应商品。同商品/窗口/anomaly_id 使用固定幂等键，重复请求可能返回旧任务，不是“重新诊断”。不要把返回已有结果当作新版本验收。

受控验证顺序：选择有数据且未用过的组合 → 确认模型费用和告警配置 → 仅提交授权数量 → 按 task_id 观察终态 → 核对 run_id、checkpoint、报告与证据。任务 succeeded 仍需人工检查结论；incomplete/failed 不自动重跑。

## 5. 有副作用的命令清单

| 入口 | 必须知道的影响 |
|---|---|
| scripts/import_retailrocket.py | 含 TRUNCATE 并重建多张业务表；不是安全的重复导入或只读预览 |
| scripts/run_detection.py | 写异常，默认自动入队；--no-diagnose 只是不入队，仍写异常 |
| POST /import/daily-stat | 一文件一事务、校验大小/行数与数值；重复合法导入仍可能重复计数 |
| POST /monitoring/reports/{run_id}/review-draft | 持久化草稿占位并最多请求一次模型；不标已审查、不自动启用经验，成本接口包含其已知用量 |
| evaluation/cases_runner.py --limit N | 按当前配置执行 Agent、写库/日志及覆盖评估结果；可能调用真实模型和外发告警 |
| scripts/run_mcp.py | 启动 stdio 工具子进程；调用会读库并写本地日志，返回数据可能进入客户端模型；不运行 Agent/LLM，不建表或写诊断 |
| scripts/run_scheduler.py | 常驻检测、入队和失效任务处理，后续可能产生费用 |
| scripts/manage_services.py stop；stop_all.bat | 强制结束进程并清理 PID 文件，可能打断在途任务 |
| scripts/backup_db.ps1 | 导出文件；不带 -NoPrune 时还可能清理旧备份 |
| scripts/migrate_worker_schema.py --apply --workers-stopped | 真实 DDL；确认标志不代替实际停服务和备份 |

不要将上述操作与离线测试合并执行；真实目标、数量和外发范围需先确认。

## 6. 离线测试与排查

```powershell
.\.venv\Scripts\python.exe -m pytest -p no:cacheprovider -q -W error::DeprecationWarning
```

运行前确认清理路径 `tests/.pytest_runtime` 在本项目 tests 内。临时 SQLite 和 Mock 验证程序规则，不证明真实 LLM 诊断质量；pytest 与 cases_runner 不可互换。PowerShell 策略不允许脚本时，直接用上述命令，不必运行 Activate.ps1 或绕过策略。

报告回归使用已有 Node.js 执行页面真实脚本，检查版本提示、显示顺序、HTML 转义、加载竞态及审查的两步提交/重复点击；不启动浏览器/服务或加载 CDN。缺少 Node.js 的机器会明确 skip 对应测试，不能当成页面测试通过；不要为测试自动安装或切换环境。可视布局验收仍与这些脚本测试分开。

| 问题 | 先看哪里 |
|---|---|
| API 启动失败 | 结构迁移提示、目标配置、服务日志；不要自动重新导入数据 |
| Worker 不领取 | 是否重复进程、队列状态、retry_after、租约与预算，见 Worker 文档 |
| 报告不准确 | 用 run_id 对照事实原值、证据覆盖、工具选择与结论强度 |
| 调用变慢/成本升高 | logs/agent_runs、tool_calls、sql_logs；区分逻辑调用与实际尝试次数 |
| Python 拒绝访问 | 解释器与基础安装目录权限；保留环境和沙箱，不转为沙箱外测试 |

验证范围、代表性问题及重要改动见[变更与验收](变更与验收.md)，完整调用流程和用量解释见[项目流程与模型用量](项目流程与模型用量.md)。
