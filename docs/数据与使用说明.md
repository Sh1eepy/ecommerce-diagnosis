# 电商商品经营异常诊断系统 —— 数据说明 · 流程 · 使用指南

> 配套代码库：`C:\Users\28277\Desktop\ANY\电商`
> 系统将电商原始行为数据转换为异常事件，由 Agent 调查原因并生成诊断报告，通过网页面板展示。

---

## 0. 系统组成

系统由三部分组成：

1. **规则引擎**：扫描商品与类目的经营指标（UV、转化率、GMV 等），发现连续下降等异常模式时产出异常事件
2. **Agent（DeepSeek 驱动）**：对每条异常事件调用只读工具调查（趋势、漏斗、同类目对比），生成结构化诊断报告：现象、原因、建议
3. **监控面板**：网页展示所有异常事件与诊断报告

## 1. 原始数据长什么样（数据集的三个 CSV）

系统用的是公开数据集 **Retailrocket**（一家真实电商的行为日志，2015 年 4 个多月）。

### ① events.csv —— 用户行为日志（275 万条，核心数据）

每行 = **一个用户在某时刻对某商品做的一个动作**。字段如下（原始列名 → 库中字段）：

| 原始列名 | 库中字段 | 含义 | 示例 |
|---|---|---|---|
| `timestamp` | `ts_ms` | 行为发生时间（毫秒时间戳） | `1430622004384` = 2015-05-03 |
| `visitorid` | `visitor_id` | 访客 ID（谁做的） | `583693` |
| `event` | `event` | 行为类型，只有 3 种 | `view` 浏览 / `addtocart` 加购 / `transaction` 成交 |
| `itemid` | `item_id` | 商品 ID（对什么做的） | `2711` |
| `transactionid` | `transaction_id` | 交易 ID（**只有成交行为有值**，浏览/加购为空） | `1cfa82d6` |

> 注意：原数据集**没有**曝光量、点击量、支付金额等独立字段，所以系统用"浏览=曝光"近似，用"成交笔数 × 商品最新价"近似 GMV（详见第 7 节口径）。

### ② item_properties*.csv —— 商品属性（890MB / 2000 万行）

每行 = 商品的一个属性（属性名是哈希编码的，只有 3 个属性未被哈希、可读懂）：

| prop | 含义 | 提取到 |
|---|---|---|
| `790` | 商品价格（`n5400.000` 格式） | `item_price` 表（41.7 万商品都有价） |
| `categoryid` | 商品所属类目（**未哈希**） | `item_category` 表 |
| `available` | 商品是否可售（下架信号） | `item_availability` 表 |

### ③ category_tree.csv —— 类目树（1669 个类目节点）

| 列 | 含义 |
|---|---|
| `categoryid` | 类目 ID |
| `parentid` | 父类目 ID（`0` 表示顶层） |

结构：**25 个顶层类目**，包含 1644 个子类目（两级分类体系）。例如顶层类目 `250` 下有 31 个子类目。

## 3. 商品与类目

### 3.1 商品

商品即原数据集中的 `item_id`，共 **417,053 个**，对应一件具体的商品（如"某款运动鞋"）。

### 3.2 类目

类目是商品的分类体系。`category_tree` 定义了 1669 个类目，分两层：

```
顶层类目（25 个）         如：250（服饰）  362（数码）  351（家居）...
   └── 子类目（1644 个）  如：250 下有 31 个子类目（250-1 男装、250-2 女装...）
```

**每个商品属于且只属于一个类目**（`item_category` 表，一个商品一行）。比如：

```
商品 2711 ──属于──► 类目 342（这个类目下有 17,231 个商品，是最大的类目）
```

### 3.3 类目有多大？（分布）

| 指标 | 数值 |
|---|---|
| 商品总数 | 417,053 |
| 有效类目数（item_category 中） | 1,225 个 |
| 平均每个类目商品数 | ~341 个 |
| 最大的类目 | 类目 342，**17,231 个商品** |
| 未分类商品（category_id=0） | 132 个（占 0.03%，可忽略） |

> 一个类目包含多个同类商品。类目级异常基于该类目下所有商品指标的加总（SUM UV/GMV 等），用于判断类目整体是否下滑，例如"类目内所有运动鞋的 GMV 整体下滑 30%"。

### 3.4 商品级异常 vs 类目级异常（核心区别）

| | 商品级异常 | 类目级异常 |
|---|---|---|
| 对象 | 单个商品 | 整个类目（含数千商品） |
| 记录 | `item_id=2711` | `item_id=0` + `category_id=342` |
| 例子 | "商品 2711 转化率连续 3 天下跌 42%" | "类目 342（1.7 万商品）的 GMV 连续下跌 30%" |
| 诊断方式 | Agent 直接查该商品 | Agent 取该类目 UV 最高的代表商品作为锚点进行诊断 |
| 用途 | 定位单品问题 | 区分单品问题与类目整体问题（PeerTool 归因） |

### 3.5 当前异常数量（2026-08 检测结果）

| 类型 | 数量 | 说明 |
|---|---|---|
| 商品级异常 | **335 条** | 417,053 个商品里有 335 个商品异常（**每条是一个独立警报**，不是重复——但一个商品可能有多条不同指标/规则的警报，比如同商品 UV 和 GMV 各报一条） |
| 类目级异常 | **543 条** | 1,137 个有数据的类目里有 543 个类目异常 |
| **合计（open）** | **878 条** | 全部待处理 |

> 面板左上角"共 878 条"就是这个数。**335 商品级**在「商品级」筛选下、**543 类目级**在「类目级」筛选下。已诊断的排在最前面（点「查看报告」看 AI 诊断结论）。

## 4. 全流程（数据 → 异常 → 诊断 → 报告 → 面板）

```
events.csv（275万行为日志）
   │ ① 导入聚合
   ▼
daily_item_stat（宽表：天×商品×维度）
   │ ② 规则引擎扫描（不碰 LLM，纯确定性规则）
   ▼
anomaly_event（878 条异常警报）←──────────┐
   │ ③ 自动创建诊断任务                     │
   ▼                                        │
task 任务队列 ──► ④ Worker 消费 ──► Agent 诊断 ──┐
   │                                        │
   ▼ ⑤ 报告落库                             │
diagnostic_report（关联 anomaly_id）────────┘
   ▼
⑥ 监控面板（网页） + ⑦ Webhook 告警（可选）
```

**每一步对应什么**：

| 步骤 | 脚本/组件 | 干什么 | 怎么触发 |
|---|---|---|---|
| ① 导入 | `import_retailrocket.py` | CSV → 宽表（35 秒/275 万行） | 手动跑一次 |
| ② 检测 | `run_detection.py` | 扫商品+类目跑规则，写异常 | 手动 / 调度器每天 00:00 |
| ③ 入队 | 检测器自动 | 新异常自动建诊断任务 | 自动（幂等） |
| ④ 诊断 | `run_worker.py` | Worker 消费任务，Agent 调 4 个只读工具取证 | 常驻进程 |
| ⑤ 报告 | Agent 自动 | 结构化报告落库 | 自动 |
| ⑥ 展示 | `uvicorn ...` | 网页面板 | 常驻进程 |
| ⑦ 告警 | `app/alerting.py` | 诊断完成 POST 到 Webhook（钉钉/企微/飞书） | `.env` 配置后自动 |

## 7. 已知口径与限制

- 原数据无独立曝光/点击/支付字段 → **漏斗 = 浏览→加购→成交** 三段
- **GMV = 成交笔数 × 商品最新价**（V1 近似，未按"当日生效价"精确 join）
- 商品属性大多已哈希编码，系统**只解释 3 个字段**：价格 / 类目 / 上下架
- 类目级异常以"该类目 UV 最高的代表商品"作为诊断对象（Agent 工具为商品级）
- 未诊断的异常：类目级（需跑补诊断脚本或等下次检测）、以及 Worker 未运行期间的新异常

## 8. 已处理的问题（摘要，详见 `docs/设计说明.md`）

| 问题 | 处理方式 |
|---|---|
| `categoryid=0` 撞自增主键 | 开启 `NO_AUTO_VALUE_ON_ZERO` |
| 聚合慢/锁死 | 分维度独立事务 + `tmp_table_size=1G` |
| 逐商品检测 5 分钟以上 | 一次查询批量加载，Python 内分组判定（秒级） |
| MySQL `Decimal × float` | 派生计算统一转 float |
| SQLite/MySQL 方言差异 | `isinstance` 兼容 + 类型转换（测试走 SQLite，已兼容两种方言） |
