# 重要变更与验收范围

按能力归纳改动、设计理由和验证边界，不按具体更新日期排列。本文件是对外摘要，不公开本机路径、进程号、凭据、运行日志、备份或用户反馈原文。

## 1. 重要改动及原因

| 改动 | 解决的问题与设计理由 |
|---|---|
| API scope、生产配置检查、输入与上传限制 | 分开读取、诊断、导入和反馈权限；拒绝非法窗口、异常归属不匹配及默认生产凭据。CSV 有界读取并采用整批事务 |
| 关闭 SDK 重试、Provider 分类退避 | 避免两层自动重试叠加；临时故障在预算内重试，认证/额度/未知错误停止，保留服务端等待要求 |
| 显式失败类型与 checkpoint 状态 | Worker 不再把 error 返回对象当作成功结果；区分等待恢复、完成、失败与停止，只有正确终态才能复用 |
| 完整步骤存档、原始预算与身份核对 | 保存证据、下一步骤和累计用量；重启不重置预算，损坏或目标不匹配的状态不得自动恢复 |
| Worker 槽位、租约/心跳及事务内凭证检查 | 避免过量领取；租约过期不等于旧线程停止，迟到执行者不能覆盖新执行者结果 |
| 显式旧表迁移、安全备份发布 | create_all 不会给旧表增列；先停服务、备份和预览。导出成功且非空才发布 SQL，失败不清理旧备份；导出仍不等于恢复验收 |
| 不确定性报告契约 | 不强迫选择主原因；保留观察事实、未知部分、待验证原因与核查动作。服务端补充数据覆盖、样本量、GMV 口径等限制 |
| 双窗口覆盖与有条件变化量 | 当前和上一窗口一起核查；缺行、零基线、零分母分别处理，不把无记录默认为零，不用单窗口同行值判断大盘历史趋势 |
| 上下文去重与请求前预算估计 | 去掉摘要与 JSON 重复传输，保留完整证据及最新修正；收紧输出、低预算收尾，减少超额和无效扩展调查 |
| 业务化报告与看板加载修复 | 展示事实、定位、限制与行动；技术引用折叠，旧报告明确未复核。区分 Key 缺失、无权限、限流、服务故障和真实空列表，旧请求不覆盖新结果 |
| 人工审查、LLM 提炼草稿与授权经验 | 反馈先预览后确认，绑定报告版本；单个提炼请求先占位、不自动重试，失败可手工填写。人工授权后才检索，来源可追溯、可停用 |
| 两类规则误判修复 | 零值谓词不跨主语/分句误套到其他指标；识别紧贴因果谓词的“可能”，仍拒绝确定性越界与数字错引 |
| MCP 可选 stdio 适配 | 原 Agent 直调工具；外部客户端复用同一 Schema、权限和查询逻辑。显式导出只读工具，限制在途数量、结果大小与调用频率 |
| 重复流程合并 | 统一四工具输入解析、指标公式、维度枚举、双窗口计算、商品/类目检测及监控空桶；保留不同事务和业务口径 |
| lifespan 与日期参数绑定 | 替换弃用接口，严格回归将 DeprecationWarning 当作错误，不用屏蔽警告掩盖兼容问题 |

实现入口及取舍见[设计说明](设计说明.md)。迁移、启停、备份和副作用见[使用说明](数据与使用说明.md)及[Worker 文档](Worker运行与恢复说明.md)。

## 2. 验证到哪一步

| 验证 | 已观察到的结果 | 不代表什么 |
|---|---|---|
| 全量离线回归 | 464 项通过，无警告、无跳过；SQLite/Mock，包含真实 SDK 的模拟 HTTP 和 Node.js 页面脚本测试 | 不能证明 MySQL 并发安全、真实模型准确性或完整浏览器安全 |
| 真实 Worker 正常执行 | 一条受控任务完成领取、续租、报告/checkpoint/任务一致落盘 | 尚未完成多进程抢占、断连和崩溃接管演练 |
| 真实 LLM 复诊 | 修复后有报告正常结束；两条补跑样例各 3 次模型调用，分别 11,419 和 11,392 tokens | 不是固定调用数、固定费用或诊断准确率样本 |
| 失败与质量边界 | 数值引用不一致被拦截；规则误判通过原始候选复核发现并修复；旧报告保留 | 规则仍可能漏判，例如把“有加购无成交”过度定位为支付问题 |
| 人工经验流程 | API/前端脚本的确认、来源核对、重复请求、失败降级、授权和停用已覆盖；部署后读取接口正常 | 尚未用用户实际反馈验收模型提炼质量或经验对后续判断的改善 |
| MCP 协议 | 进程内现代/兼容模式发现和调用通过，结构化结果与原工具一致 | 未完成外部客户端和真实操作系统 stdio 管道验收 |
| 备份与迁移 | 完成受控导出、列迁移及启动核查 | 尚未在隔离库恢复备份验证可用性 |

测试计数是本次发布前的本地结果；远端 CI 需单独查看。用量统计只包含已知 usage，配置上限不是硬账单封顶。完整工作流程及调用数解释见[项目流程与模型用量](项目流程与模型用量.md)。

## 3. 下一步优先级

1. 增强自然语言与证据的对应关系，区分“观察到零成交”和“已定位支付故障”；对反复相同的无效修正停止浪费，给出准确失败说明。
2. 用实际人工反馈验证提炼忠实度、适用条件和同类经验检索，不把模型草稿直接当正确答案。
3. 在隔离 MySQL 演练多 Worker 竞争、崩溃恢复与备份恢复。
4. 多用户使用前补数据归属隔离、最小数据库授权；真实写操作需审批、幂等和补偿，告警需可靠投递。

完整待办见[生产化问题与设计对照](生产化问题与设计对照.md)。保留当前“有人复核的经营诊断原型”定位，不以一次成功、模型置信度或测试通过宣称生产可用。
